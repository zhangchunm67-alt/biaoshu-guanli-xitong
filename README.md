# 标书管理系统

面向腾宝科技现有投标材料的本地管理工具。项目流程为：上传标书 → 核对图片材料 → 核对文字材料 → 导出标书。材料库分为图片材料和文字材料，项目不再要求选择行业。旧行业分类接口保留兼容。

## 启动

macOS 双击 `启动标书管理系统.command`，浏览器打开 http://127.0.0.1:8766 。保留启动窗口，按 Control+C 关闭服务。

启动器依次选择本目录虚拟环境、Codex 已安装的 Python 环境或可用的本机 Python。均不可用时，在本目录创建 `.venv` 并安装 `requirements.txt`；仅首次安装依赖需要网络。日常材料处理在本机完成。

也可以手动启动：

```sh
python3 -m venv .venv
.venv/bin/python3 -m pip install -r requirements.txt
.venv/bin/python3 server.py --open
```

Windows 使用 `start.bat`，需要先安装 Python 3.10 或更高版本。Windows 启动器尚未经实机验证。

## 首次数据

首次启动会从父目录原有台账导入 5 组材料、55 张图片，复制到系统数据目录。原始台账、Word 和图片不作修改。若将代码单独拷到其他位置且没有原材料，仍可从界面新增材料和上传模板。

| 通用栏目 | 初始材料 |
| --- | --- |
| 法定代表人（负责人）身份证明 | 身份证正反面附件 |
| 法定代表人（负责人）授权委托书 | 代理人身份证正反面附件 |
| 营业执照 | 腾宝公司营业执照 |
| 2023-2024年财务审计报告 | 2023 年 26 张，2024 年 24 张，按年度分组 |
| 税收和社会保障资金缴纳凭证 | 待补充 |
| 公司介绍 | 待整理成独立材料 |
| ISO相关资质证书 | 待补充 |

身份证图片仅是附件，证明及授权正文须按本次项目核对。审计报告中的会计师事务所营业执照随报告归档，不会单独识别为投标主体执照。

原文找到意思对应的材料条目即可自动定位，名称不必完全相同，例如“营业执照”可匹配“营业执照副本复印件（加盖公章）”，“公司介绍”可匹配“单位基本概况”。优先使用正式附件位置；没有时直接在对应条目后填入材料，包括提交清单中的条目。重复清单只选一处，表格条目填入该条目所在单元格；评分、合同条款及其他主体的证件不作为自动插入位置。只有识别到通用材料要求却没有对应条目或附件位置时，才在文末新增材料区。身份证附件仍提示证明/授权正文须另行核对。旧项目打开时更新自动位置，保留已选材料、备注、人工指定位置、手动缺项和跳过决定，位置更新后须重新核对。

## 操作流程

1. 在“材料库”维护材料名称、栏目、主体、年度、版本、有效期、图片或文字内容。填写时即时显示字段错误和保存前提醒；有效期格式、过期材料、主体、审计年度及内容缺失等问题须修正后才能保存。编辑材料时提前显示对已关联标书的影响。图片支持预览、顺序调整和旋转；材料详情中的“批量移除”支持多选、全选和取消全选，确认后一次移出所选图片，保留本地原件并取消关联项目的旧确认。
2. 在“标书项目”上传 `.doc` 或 `.docx`（单个文件最大 30 MB），或使用文件夹中的测试 Word 创建项目。后缀是 `.doc`、实际内容为 `.docx` 的文件可直接读取；真正旧版 `.doc` 会在本机转换。系统保留上传原件、工作模板及各自指纹，每次导出均从工作模板开始，重复导出不会叠加上一轮图片。旧版转换后须在 Word 中核对表格、分页和目录。
3. 核对每个通用栏目的模板位置、材料、年度要求和处理方式。可以改选位置、材料，标记待补或跳过。保存后查看重新校验结果。每个匹配项下方直接预览已选材料：1–2 页全部展示，超过 2 页按每份材料展示首页和末页及总页数；点击图片或“查看完整材料”可打开材料详情逐页查看。
在“模板插入位置”下点击“预览插入位置”，可查看保留原排版的标书页面及插入标记，支持翻页、输入页码、缩放、隐藏标记和返回插入页。通用、专用核对使用同一入口：未选位置时也可打开原页；在预览上方选择位置后跳转并标记，改选同步到当前核对项，需回到核对页保存。刚改选但未保存的位置也可预览，预览不会保存修改或代替确认。原文后追加、表格占位符及空白单元格按导出的同一定位规则显示。首次预览需本机 LibreOffice 渲染；预览页码是本机渲染页序，Word 中的最终分页可能略有差异。
补充或修改材料后，已有项目会同步校验。原来自动保留为缺项的栏目有唯一适用材料时自动匹配，并取消该项旧确认；存在多个版本时需人工选择。手动跳过、手动保留缺项及已经选定的材料不会被自动替换。旧项目重新打开即可同步，无需重新扫描模板。

4. 图片材料保存且没有阻断问题后，点击“下一步：核对文字材料”。系统加载启用的文书模板栏目及有文字材料的栏目，不要求选择行业，也不带入空的旧行业栏目。投标函、授权书、承诺函分别保留正文位置；选择文字材料时会校验文书类型。可以搜索、分页和预览材料，空项可以记录待补或跳过。
5. 保存文字材料核对后进入导出页，点击“导出”生成初稿。界面不再要求逐项或批量打勾；有材料或位置错误时仍阻止导出。初稿保留待补/跳过标记。兼容接口的 `reviewed` 模式仍要求全部栏目就绪并人工确认，不能把初稿当作已核对版本。

导出时显示按处理阶段更新的进度条和“预计还需”时间，根据材料数量、历史速度及当前进度修正，超出可用估算时提示重新估算。点击“后台运行”可关闭弹窗继续操作，右下角显示任务并提供完成后的下载入口。刷新或关闭浏览器不取消任务，本地服务需要保持运行；重新打开页面会读取任务状态。导出基于提交时的材料记录，不会覆盖运行期间的新修改。同一项目运行中的任务重复点击会返回原任务；服务意外停止后，未完成任务标为中断，可重新提交。初稿正文仍标注“仅供内部核对，不可直接投标”及待补内容。

“栏目设置”支持增加通用栏目、维护别名和启停。修改规则后重新扫描相关项目。“专用材料”按行业进入栏目，支持搜索、核对状态筛选和分页。材料详情可查看来源、修改归类和跨行业关联，支持图片排序、旋转、追加、多选移除及恢复。专项资格栏目无真实材料时保持为空。

历史导入材料统一为“待核对”。人员和合作方使用实际证明主体；未知有效期、历史过期、缺页和授权范围需核对。专用材料不会自动套入通用栏目；只有本项目选中的专用分类、材料及位置才参与核对与 Word 导出。历史业绩的过期日期作为使用提醒；已过期的人员、资格及授权证明、已停用材料、无有效插入位置或图片不可用时阻止确认。

交付的图片 ZIP 与“批量导入清单.json”可通过 `scripts/import_special.py --manifest <清单路径> --zip <图片包路径>` 重新导入；每份材料单独保存，中断可重试，已有材料及人工核对状态不会被覆盖。

## 无违法违规记录查询截图

“通用材料”内置三项官方查询的全自动条件检测：失信被执行人、重大税收违法失信主体、政府采购严重违法失信行为记录名单。按用户要求，**必须三项全自动完成，否则不启用**。这三项为受管栏目，初始停用，原有 7 个匹配栏目不变。

2026-10-16 实站检查：法院查询返回 403 访问限制；信用中国的税收及政府采购查询在提交主体后要求验证码。当前自动归档保持停用，没有生成“无记录”材料。三个来源的成功结果结构尚未完成实站验证，恢复访问后仍须补充验证才能启用。

“检测全自动条件”会向三个固定官方入口提交当前投标主体，后台检查页面和结果。验证码、访问失败、空白表格和无法确认的结果都会阻止启用。截图仅作为本地诊断保存；普通栏目设置无法绕过归档门槛。脚本与使用方式见 [CREDIT_CAPTURE.md](CREDIT_CAPTURE.md)。

## 匹配规则和边界

- 自动匹配已启用的图片材料栏目；文字材料在下一步分别选择模板及位置。系统不生成报价、签章或授权正文。
- Word 目录域、目录样式、已识别的手工目录和页码索引前清单不能作为插入位置。删除目录后空行使目录域结束标记并入正文标题时，该标题仍保留为位置。真实重复正文保留独立位置；旧目录位置失效时要求重新核对。
- 纳税与社保凭证在共享分类中分别校验；明确月份按材料名称及版本登记的所属期核对，支持“2025年1-6月”“1至6月”等写法，提交或截止日期不当作所属期，合并栏目要求覆盖两类凭证。只能部分覆盖年度、凭证类型或月份时仍自动预选，并列出缺少的部分；重叠版本、无法完整识别的期限不自动猜选。“近六个月”等相对期限需按投标截止日人工核对。
- 按原文档结构定位，不依赖旧页码。不同项目即使模板同名，也使用独立模板副本和映射。
- 年度以材料登记信息为准；标题要求多年度时，要检查全部年度是否覆盖。栏目别名不能绕过年度限制。
- 通用材料主体以当前腾宝公司为范围；专用材料允许人员、合作方等实际证明主体，须人工核实其项目适用性。有效期未登记会提示核对，不能视为已经验证有效。
- 模板支持 `.doc` / `.docx`，材料支持图片和文字。旧版 `.doc` 转换需要本机 LibreOffice；优先使用 Codex 已安装的转换工具，也支持系统安装的 LibreOffice 或通过 `BID_LIBREOFFICE` 指定可执行文件。缺少转换工具时，页面提示在 Word 中另存为 `.docx`。扫描 PDF、宏文档、复杂浮动文本框等需要先整理为受支持格式。
- 上传模板中的历史项目名、姓名、日期、授权范围和业务陈述会保留。系统不擅自替换、不编造缺失资料。现有测试 Word 含历史项目内容，导出后应人工检查。
- Word 目录会请求更新域；打开导出文件后更新整个目录。正文或索引表中手写的页码不会自动重算。
- 低分辨率身份证图片会保留原始素材，放大不能增加清晰度，打印前需核对。

## 本地存储与备份

所有运行数据在 `data/`，包含 SQLite 数据库、材料副本、原模板副本及导出文件。停止服务后复制整个 `data/` 目录即可备份；恢复时替换为同一版本的完整备份。不要只复制数据库而遗漏图片和模板。

代码已初始化为本地 Git 仓库，`data/`、虚拟环境及测试输出不进入版本管理。材料不会因代码提交而提交。服务仅监听 `127.0.0.1`，当前版本面向本机使用，没有团队账号和远程共享功能。

可用 `--port 端口号` 修改端口，`--data-dir 路径` 指定独立数据目录。非默认数据目录不自动读取业务材料，只有显式 `--seed` 才导入父目录来源。

## 验证

在已安装依赖的 Python 环境执行：

```sh
python3 -m unittest discover -s tests -v
```

测试覆盖年度约束、材料缺失、确认门槛、精确定位、导出、持久化和上传验证。端到端测试在临时数据目录中运行，不会修改日常使用的数据。

安装 `package.json` 中的 Playwright 及其 Chromium 后，可运行 `npm run test:workflow` 验证四步页面流程、专用材料搜索分页、预览、导出及重新打开。`BID_TEST_PYTHON` 可指定已安装 Python 依赖的解释器；默认自动清理测试数据和截图。

## 代码组成

- `server.py`：本地接口、数据存储、导入与下载。
- `engine.py`：Word 栏目识别、匹配校验与导出。
- `word_import.py`：Word 格式识别、旧版 `.doc` 本地转换和临时文件清理。
- `location_preview.py`：原页渲染、插入点坐标与按需页面图片；运行期最多缓存两份模板，停止服务时清理。
- `static/`：中文管理界面，无外部字体、脚本或 CDN。
- `tests/`：回归及端到端验证。
- `CONTRACT.md`：接口和数据结构说明，便于继续扩展。
- `credit_service.py`：后台查询任务、受管栏目及证据归档门槛。
- `scripts/credit_capture.cjs`：固定官方页面检测与截图脚本，不处理验证码。
## 授权书图片材料

授权委托书标题和正文只由文字模板填写；授权书图片栏目只填充代理人身份证等证件图片。不再提供正文填写开关、项目名称、职务和签署日期等表单，不生成或替换授权书正文。模板原文与原有空白字段保留；正文、人员、日期和签章由商务核对。

图片只插入原文单独标注的“被授权人身份证复印件”“委托代理人护照复印件”等证件复制件附件位置或对应条目之后（号码填写栏、真实性声明不算），包括授权书正文后的附件说明行；原文没有这类位置时，图片栏目记为缺项，不追加到文末材料区。已有正文与所选代理人明确不符、原节已含证件图片、图片不可用或证件过期时，仍需先处理材料问题。未填写授权书正文不阻止图片填充。

旧项目打开后自动移除正文填写设置，保留所选图片、位置及备注；曾启用正文填写的栏目取消旧确认，仍可导出初稿；复核版须重新确认。真实案例浏览器回归使用独立数据目录：设置 `BID_AUTH_QA_DIR`，运行 `tests/prepare_authorization_cases.py`，再运行 `tests/test_authorization_flow.cjs`。该回归需要原始考题及本机已核对的证件材料，不修改日常材料库。

### 栏目识别更新（2026-10-22）

系统分别判断“原文需要什么材料”和“图片应插在哪里”。需求可从正文、评分表和附件说明提取，需求证据保留在项目数据中，核对页已移除展开依据和提交要求标签。财务报告年度支持从正文读取和“2024或2025”替代要求。

优先使用实际应答区域和身份证附件表格，识别无标题样式的附件、小节与并列清单边界，避免插入下一栏目。没有正式位置时，按同义名称、材料类型和常见修饰词匹配原文条目，不要求字段名完全相同；通用材料及四类专用材料均支持这一定位规则。相同清单条目择一定位，多个独立专用应答栏目或跨行业共用条目仍需核对。只有识别到通用材料要求、却找不到对应条目或附件位置时才回退到文末。旧项目自动位置规则升级会取消受影响项的旧确认，保留人工指定位置、已选材料和备注。本次未增加专用材料自动选取、PDF/OCR或授权书正文填写。
