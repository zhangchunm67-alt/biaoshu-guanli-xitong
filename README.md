# 标书管理系统

面向腾宝科技的本地标书编制与材料管理工具。工作台使用四步编制流程，上传页同时提供项目名称、继续已有项目和已有模板入口。 各页面右上角提供“新建项目”，点击后进入招标文件上传页；已有投标模板仍通过上传页的独立入口填充材料。

## 从招标文件编制

1. **招标文件解读**　直接上传本次采购方发布的一份 DOCX 或 DOC，最大 50 MB。项目名称选填，留空时使用文件名。旧版 DOC 需要本机 LibreOffice 转换；PDF 或扫描件须先转为 Word。默认阅读五类采购要求与只读原文依据，发现问题时展开“修改解读”。待核对事项合并显示一次；确认前须勾选已核对待核对事项，删除资格/格式要求也须逐项确认，避免漏掉响应栏目。确认要求后进入目录。
2. **目录编写**　默认只显示整本目录预览，需要调整时展开“修改目录”，支持增删、改名、上下移动和升降层级。章节的采购要求关联由系统保留，无须手动多选。删除仍需响应的章节会提示具体采购要求；不适用的要求须先在招标解读中修正。采购指定原表及其合并单元格、报价小计栏、表注和签章位保留。保存后 Word 与预览同步更新，核对后点击“确认目录，进入系统填充”。
3. **系统填充**　先核对文字，再核对图片材料。从招标文件生成的目录中，已有投标函、承诺函或法定代表人授权书章节时，自动保留该章节原文，不再要求选择同类文字模板或显示模板缺项；原文预览仍可查看。身份证等图片附件继续按实际位置填充；关联授权书底部时，按授权人、代理人的顺序附双方身份证，姓名与正文不符时阻止导出。原文中的人员、项目、日期、签章及空白仍须人工核对。点击下一步时，未完成事项会显示具体原因，并自动定位、高亮对应栏目；多项问题可逐项点击定位，未保存的修改先引导到“保存核对”。
4. **编写投标文件**　上传业务人员提供的相关项目案例包，点击“生成初稿正文”，也可在选中章节后点击“生成本章正文”或“重新生成本章”。系统按已确认采购要求、目录、已选材料与写作规则生成候选，逐章展示来源、待补项和冲突。核对后可逐章或批量采纳可用候选。写完正文后进入“废标红线扫描”：对照已确认红线检查材料缺漏与空章，逐条勾选确认后再导出含材料与正文的整本 Word 初稿。保留手工编写、保存入口；在 Word 中填写固定原表并更新目录，提交前核对待补项、页码、报价、签章和递交方式。

第四步已内置 `skills/tender-bid-writing/SKILL.md`，按 [接入约定](SKILL2_HANDOFF.md) 生成候选正文。采购已有的授权书、报价表和证明材料保持原有内容，空白字段仍须核对填写；案例上传不会重复生成这些原表。

案例支持 DOC、DOCX、PDF、PPTX、TXT、MD 和 ZIP，可多选，合计最多 50 MB。系统读取文字并保留文件与段落/页码出处；扫描页、图片和不可读文件会明确提示，不做 OCR。所有案例均不可读时不能生成。重新上传会替换当前案例包并使旧候选失效，已采纳正文保留。生成期间可以离开当前页面，返回后继续查看；服务停止会中断未完成任务，可重新生成。

保存一章的手工修改，只使该章旧候选待更新；其他未受影响章节仍可采纳。单章重新生成保留其他章节候选及已保存正文，失败时也不删除旧候选。采购要求、目录、材料或案例这些共享依据发生变化时，仍须重新生成受该输入版本影响的候选；采纳前继续检查输入版本和人工修改冲突。

旧编制链接保留兼容。历史工作稿可从“标书项目”页查看原来保存的正文、材料核对记录及已有导出。若有正文需要人工对照，历史工作稿入口将给出提示。

系统内置本目录下的 `skills/bid-response-framework`，无需另行安装个人 Skill。采购要求与目录在本地提取，保留可回查的原文依据，由用户核对确认后进入填充；该阶段不调用模型。

目录固定包含投标主体的“营业执照”：采购原文未提及时仍补充章节和材料位置，已有时不重复；新生成及保存目录时生效。新增营业执照章节位于“公司介绍”之前，与公司介绍同级；没有公司介绍时放入资格证明部分，否则单列。用户补充项不计入采购方强制资格要求，也不虚构原文出处。

招标解读进入目录编写时，仅在采购原文要求分册时分别生成商务标、技术标目录；原文未要求时保留统一目录。采购方规定的分册名称、顺序、章节归属及单列资格标均须保留。营业执照与公司介绍在同一部分相邻排列，营业执照在前；若原文明确规定两项分别位于不同分册，保留必交原位置，并在公司介绍前补充营业执照。目录、HTML 和整本 Word 使用同一编排计划，确认后继续在整本工作稿中填充。

图片式附件保留原图，并显示人工核对提示；本轮没有 OCR，不能把图片中的表格变成可编辑单元格。外部报价或评分附件未随主件上传时，会标记缺件，不补造其内容。样本回归通过不代表任意采购文件都能自动完整提取。

正文生成使用已忽略的 `.env.local` 配置：`OPENAI_API_KEY`、`BID_OPENAI_MODEL`（默认 `gpt-5.6-terra`）、`BID_REASONING_EFFORT`（默认 `medium`）；也可用 `BID_WRITING_MODEL` 单独指定模型，`BID_WRITING_ENABLED=off` 关闭正文生成。环境变量优先。点击第四步生成时，会发送相关采购要求与原文、案例文字、本项目所选材料的文字与元信息、已有正文和业务补充。请求使用 `store=false`，密钥不返回浏览器。响应通过流式接收，在收到完整结束结果后校验；数据不完整或无法解析时自动重试一次，失败不覆盖已有正文。未配置时仍可人工核对与编写。

旧框架保留原结果；重新上传采购原件可使用新编辑流程。修改已用于填充的目录时，原工作稿、材料核对和导出保留在历史入口；重新确认后，仍存在的稳定章节自动带入已写正文，材料位置需要重新核对。多窗口保存与最终确认均检查版本，过期页面不能覆盖或确认新结果。

启动后访问 [招标文件解读](http://127.0.0.1:8766/?workflow=analysis) 可直接上传。

## 启动

macOS 双击 `启动标书管理系统.command`，浏览器打开 http://127.0.0.1:8766 。保留启动窗口，按 Control+C 关闭服务。

启动器依次选择本目录虚拟环境、Codex 已安装的 Python 环境或可用的本机 Python。均不可用时，在本目录创建 `.venv` 并安装 `requirements.txt`；仅首次安装依赖需要网络。日常材料处理在本机完成。

也可以手动启动：

```sh
python3 -m venv .venv
.venv/bin/python3 -m pip install -r requirements.txt
.venv/bin/python3 server.py --open
```

Windows 使用 `start.bat`，需要先安装 Python 3.10 或更高版本。Windows 启动器尚未经实机验证。

## 首次数据

首次启动会从父目录原有台账导入 5 组材料、55 张图片，复制到系统数据目录。原始台账、Word 和图片不作修改。若将代码单独拷到其他位置且没有原材料，仍可从界面新增材料和上传模板。

| 通用栏目 | 初始材料 |
| --- | --- |
| 法定代表人（负责人）身份证明 | 身份证正反面附件 |
| 法定代表人（负责人）授权委托书 | 代理人身份证正反面附件 |
| 营业执照 | 腾宝公司营业执照 |
| 2023-2024年财务审计报告 | 2023 年 26 张，2024 年 24 张，按年度分组 |
| 税收和社会保障资金缴纳凭证 | 待补充 |
| 公司介绍 | 待整理成独立材料 |
| ISO相关资质证书 | 待补充 |

身份证图片仅是附件，证明及授权正文须按本次项目核对。审计报告中的会计师事务所营业执照随报告归档，不会单独识别为投标主体执照。

原文找到意思对应的材料条目即可自动定位，名称不必完全相同，例如“营业执照”可匹配“营业执照副本复印件（加盖公章）”，“公司介绍”可匹配“单位基本概况”。优先使用正式附件位置；没有时直接在对应条目后填入材料，包括提交清单中的条目。重复清单只选一处，表格条目填入该条目所在单元格；评分、合同条款及其他主体的证件不作为自动插入位置。只有识别到通用材料要求却没有对应条目或附件位置时，才在文末新增材料区。身份证附件仍提示证明/授权正文须另行核对。旧项目打开时更新自动位置，保留已选材料、备注、人工指定位置、手动缺项和跳过决定，位置更新后须重新核对。

## 已有模板的材料填充

1. 在“材料库”维护材料名称、栏目、主体、年度、版本、有效期、图片或文字内容。填写时即时显示字段错误和保存前提醒；有效期格式、过期材料、主体、审计年度及内容缺失等问题须修正后才能保存。编辑材料时提前显示对已关联标书的影响。图片支持预览、顺序调整和旋转；材料详情中的“批量移除”支持多选、全选和取消全选，确认后一次移出所选图片，保留本地原件并取消关联项目的旧确认。
2. 在“标书项目”上传 `.doc` 或 `.docx`（单个文件最大 30 MB），或使用文件夹中的测试 Word 创建项目。后缀是 `.doc`、实际内容为 `.docx` 的文件可直接读取；真正旧版 `.doc` 会在本机转换。系统保留上传原件、工作模板及各自指纹，每次导出均从工作模板开始，重复导出不会叠加上一轮图片。旧版转换后须在 Word 中核对表格、分页和目录。
3. 先核对文字材料：系统加载文书模板及有文字材料的栏目，选用与文书类型对应的模板并保存。授权书优先使用采购指定格式，材料库模板作为核对和填充来源；不自动编造授权事实。可以改选位置、材料，标记待补或跳过。保存后查看重新校验结果。每个匹配项下方直接预览已选材料：1–2 页全部展示，超过 2 页按每份材料展示首页和末页及总页数；点击图片或“查看完整材料”可打开材料详情逐页查看。
在“模板插入位置”下点击“预览插入位置”，可查看保留原排版的标书页面及插入标记，支持翻页、输入页码、缩放、隐藏标记和返回插入页。通用、专用核对使用同一入口：未选位置时也可打开原页；在预览上方选择位置后跳转并标记，改选同步到当前核对项，需回到核对页保存。刚改选但未保存的位置也可预览，预览不会保存修改或代替确认。原文后追加、表格占位符及空白单元格按导出的同一定位规则显示。首次预览需本机 LibreOffice 渲染；预览页码是本机渲染页序，Word 中的最终分页可能略有差异。
补充或修改材料后，已有项目会同步校验。原来自动保留为缺项的栏目有唯一适用材料时自动匹配，并取消该项旧确认；存在多个版本时需人工选择。手动跳过、手动保留缺项及已经选定的材料不会被自动替换。旧项目重新打开即可同步，无需重新扫描模板。

4. 文字材料保存且没有阻断问题后，点击“下一步：核对图片材料”。核对图片、年度和位置；授权书正文唯一明确时，双方身份证自动关联其底部，无需独立身份证占位符。多份授权书存在歧义时需人工指定对应授权书，不能跨包件猜选。预览直接显示已选授权书正文与附件位置。
5. 保存图片材料核对后进入导出页，点击“导出”生成初稿。界面不再要求逐项或批量打勾；有材料或位置错误时仍阻止导出。初稿保留待补/跳过标记。兼容接口的 `reviewed` 模式仍要求全部栏目就绪并人工确认，不能把初稿当作已核对版本。

导出时显示按处理阶段更新的进度条；处理中的预计用时固定显示为“预计还需约 30 秒”。点击“后台运行”可关闭弹窗继续操作，右下角显示任务并提供完成后的下载入口。刷新或关闭浏览器不取消任务，本地服务需要保持运行；重新打开页面会读取任务状态。导出基于提交时的材料记录，不会覆盖运行期间的新修改。同一项目运行中的任务重复点击会返回原任务；服务意外停止后，未完成任务标为中断，可重新提交。初稿正文仍标注“仅供内部核对，不可直接投标”及待补内容。

“栏目设置”支持增加通用栏目、维护别名和启停。修改规则后重新扫描相关项目。“专用材料”按行业进入栏目，支持搜索、核对状态筛选和分页。材料详情可查看来源、修改归类和跨行业关联，支持图片排序、旋转、追加和多选移除；移出后保留本地原件，当前界面未提供恢复入口。专项资格栏目无真实材料时保持为空。

历史导入材料统一为“待核对”。人员和合作方使用实际证明主体；未知有效期、历史过期、缺页和授权范围需核对。专用材料不会自动套入通用栏目；只有本项目选中的专用分类、材料及位置才参与核对与 Word 导出。历史业绩的过期日期作为使用提醒；已过期的人员、资格及授权证明、已停用材料、无有效插入位置或图片不可用时阻止确认。

交付的图片 ZIP 与“批量导入清单.json”可通过 `scripts/import_special.py --manifest <清单路径> --zip <图片包路径>` 重新导入；每份材料单独保存，中断可重试，已有材料及人工核对状态不会被覆盖。

## 同事投稿材料与案例

材料库新增“案例库”和“投稿入库”。同事（包括通过花生壳外网访问的同事）可以提交材料和项目案例，由本机管理员核对后入库。

1. **提交**：在材料库的“投稿入库”或“案例库”点击“提交材料”“提交案例”，并填写提交人。
   - 材料可上传图片（单张不超过 15 MB，每次最多 100 张），也可填写文字内容；可选建议栏目，不确定时留空，由审核人归类。
   - 案例支持 DOC、DOCX、PDF、PPTX、TXT、MD、ZIP，合计不超过 50 MB，须含可读取的文字。
   - 花生壳外网的“新增材料”按钮改为“提交材料”。
2. **暂存**：投稿存放在 `data/submissions/`，入库前不进入材料库、项目自动匹配或正文写作。待审核投稿最多 100 份，合计不超过 1 GB。
3. **审核（仅本机入口）**：在“投稿入库”查看图片缩略图或下载案例文件，然后：
   - 材料按材料库同一规则（栏目、主体、年度、有效期）核对后入库，材料详情记录“投稿 · 提交人”；
   - 案例加入案例库；
   - 不符合要求的填写原因退回。
   入库或退回后，暂存文件即删除。
4. **外网可见范围**：花生壳映射口只能提交投稿、查看处理状态和退回原因，看不到已提交的文件名、图片或案例原件，也不能入库、退回或下载。
5. **使用案例**：第四步“编写投标文件”中展开“从案例库选择”，勾选后点击“使用所选案例”，所选案例将替换当前案例包，文件显示为“案例库/案例名称/文件名”。在案例库中“移出案例库”只影响以后的选择，已组成的案例包不变。

## 无违法违规记录查询截图

“通用材料”内置三项官方查询的全自动条件检测：失信被执行人、重大税收违法失信主体、政府采购严重违法失信行为记录名单。按用户要求，**必须三项全自动完成，否则不启用**。这三项为受管栏目，初始停用，原有 7 个匹配栏目不变。

2026-10-16 实站检查：法院查询返回 403 访问限制；信用中国的税收及政府采购查询在提交主体后要求验证码。当前自动归档保持停用，没有生成“无记录”材料。三个来源的成功结果结构尚未完成实站验证，恢复访问后仍须补充验证才能启用。

“检测全自动条件”会向三个固定官方入口提交当前投标主体，后台检查页面和结果。验证码、访问失败、空白表格和无法确认的结果都会阻止启用。截图仅作为本地诊断保存；普通栏目设置无法绕过归档门槛。脚本与使用方式见 [CREDIT_CAPTURE.md](CREDIT_CAPTURE.md)。

## 匹配规则和边界

- 先选择文字模板及位置，再核对已启用的图片材料栏目。系统不生成报价、签章或授权正文。
- Word 目录域、目录样式、已识别的手工目录和页码索引前清单不能作为插入位置。删除目录后空行使目录域结束标记并入正文标题时，该标题仍保留为位置。真实重复正文保留独立位置；旧目录位置失效时要求重新核对。
- 纳税与社保凭证在共享分类中分别校验；明确月份按材料名称及版本登记的所属期核对，支持“2025年1-6月”“1至6月”等写法，提交或截止日期不当作所属期，合并栏目要求覆盖两类凭证。只能部分覆盖年度、凭证类型或月份时仍自动预选，并列出缺少的部分；重叠版本、无法完整识别的期限不自动猜选。“近六个月”等相对期限需按投标截止日人工核对。
- 按原文档结构定位，不依赖旧页码。不同项目即使模板同名，也使用独立模板副本和映射。
- 年度以材料登记信息为准；标题要求多年度时，要检查全部年度是否覆盖。栏目别名不能绕过年度限制。
- 通用材料主体以当前腾宝公司为范围；专用材料允许人员、合作方等实际证明主体，须人工核实其项目适用性。有效期未登记会提示核对，不能视为已经验证有效。
- 模板支持 `.doc` / `.docx`，材料支持图片和文字。旧版 `.doc` 转换需要本机 LibreOffice；优先使用 Codex 已安装的转换工具，也支持系统安装的 LibreOffice 或通过 `BID_LIBREOFFICE` 指定可执行文件。缺少转换工具时，页面提示在 Word 中另存为 `.docx`。扫描 PDF、宏文档、复杂浮动文本框等需要先整理为受支持格式。
- 上传模板中的历史项目名、姓名、日期、授权范围和业务陈述会保留。系统不擅自替换、不编造缺失资料。现有测试 Word 含历史项目内容，导出后应人工检查。
- Word 目录会请求更新域；打开导出文件后更新整个目录。正文或索引表中手写的页码不会自动重算。
- 低分辨率身份证图片会保留原始素材，放大不能增加清晰度，打印前需核对。

## 本地存储与备份

所有运行数据在 `data/`，包含 SQLite 数据库、材料副本、原模板副本及导出文件。停止服务后复制整个 `data/` 目录即可备份；恢复时替换为同一版本的完整备份。不要只复制数据库而遗漏图片和模板。

代码已初始化为本地 Git 仓库，`data/`、虚拟环境及测试输出不进入版本管理。材料不会因代码提交而提交。默认仅监听 `127.0.0.1`；远程访问模式下会同时开两个端口：远程口只给同事编制（永不下发材料），本机环回口专门维护材料库、查看与导出材料，避免伪造 `Host` 绕过。

可用 `--port 端口号` 修改端口，`--data-dir 路径` 指定独立数据目录。非默认数据目录不自动读取业务材料，只有显式 `--seed` 才导入父目录来源。

## 远程访问：局域网、节点与花生壳

服务器电脑一直开着跑系统，同事通过以下任一方式在线编制标书，完整步骤见 [局域网与节点访问方案](局域网与节点访问方案.md)：

- **腾宝AI WiFi 局域网直连**：同事连同一 WiFi，打开 `http://服务器IP:8766/`。
- **节点（局域网外）**：同事先连公司节点，再用节点可达的服务器地址访问。
- **花生壳**：外网域名映射到服务器 `127.0.0.1:8766`。

配置写在 `.env.oray`（由 `.env.oray.example` 复制）：`ORAY_LAN_HOSTS` 填局域网/节点地址，`ORAY_PUBLIC_HOST` 填花生壳域名，`ORAY_ACCESS_TOKEN` 填至少 12 位的口令（可用中文）。macOS 双击 `启动花生壳访问.command`，Windows 双击 `启动局域网访问.bat`。

远程入口（8766）可做招标解读、目录、正文等编制，并可提交材料和案例；材料库维护（新增、修改、停用材料与栏目）、查看材料原件、审核投稿、下载含材料的导出只能在服务器本机打开 `http://127.0.0.1:8767/`。登录错误多次会临时锁定；登录有效期 12 小时；登录、修改、下载等操作记录在 `data/logs/access.log`（不记正文）。电脑休眠或关闭后远程不可用；请定期备份整个 `data/`。

## 验证

在已安装依赖的 Python 环境执行：

```sh
python3 -m unittest discover -s tests -v
```

测试覆盖年度约束、材料缺失、确认门槛、精确定位、导出、持久化和上传验证。端到端测试在临时数据目录中运行，不会修改日常使用的数据。

废标红线识别的精确率、召回率按 [评测方案](REDLINE_EVAL.md) 对照人工金标准测量，脚本为 `scripts/eval_redline.py`。

安装 `package.json` 中的 Playwright 及其 Chromium 后，可运行 `npm run test:workflow` 验证四步页面流程、专用材料搜索分页、预览、导出及重新打开；`npm run test:contributions` 以花生壳映射口和本机入口两个浏览器验证投稿、审核入库、退回及第四步选用案例库。`BID_TEST_PYTHON` 可指定已安装 Python 依赖的解释器；默认自动清理测试数据和截图。

## 代码组成

- `server.py`：本地接口、数据存储、导入与下载。
- `engine.py`：Word 栏目识别、匹配校验与导出。
- `word_import.py`：Word 格式识别、旧版 `.doc` 本地转换和临时文件清理。
- `location_preview.py`：原页渲染、插入点坐标与按需页面图片；运行期最多缓存两份模板，停止服务时清理。
- `static/`：中文管理界面，无外部字体、脚本或 CDN。
- `tests/`：回归及端到端验证。
- `CONTRACT.md`：接口和数据结构说明，便于继续扩展。
- `credit_service.py`：后台查询任务、受管栏目及证据归档门槛。
- `contributions.py`：同事投稿的暂存、本机审核入库与案例库。
- `framework_review.py`：五类要求校验、原文绑定、稳定章节与目录修订。
- `writing_model.py`：候选正文生成、来源与结构校验及本机写作配置。
- `scripts/credit_capture.cjs`：固定官方页面检测与截图脚本，不处理验证码。
## 授权书图片材料

授权委托书标题和正文只由文字模板填写；授权书图片栏目只填充代理人身份证等证件图片。不再提供正文填写开关、项目名称、职务和签署日期等表单，不生成或替换授权书正文。模板原文与原有空白字段保留；正文、人员、日期和签章由商务核对。

图片只插入原文单独标注的“被授权人身份证复印件”“委托代理人护照复印件”等证件复制件附件位置或对应条目之后（号码填写栏、真实性声明不算），包括授权书正文后的附件说明行；原文没有这类位置时，图片栏目记为缺项，不追加到文末材料区。已有正文与所选代理人明确不符、原节已含证件图片、图片不可用或证件过期时，仍需先处理材料问题。未填写授权书正文不阻止图片填充。

旧项目打开后自动移除正文填写设置，保留所选图片、位置及备注；曾启用正文填写的栏目取消旧确认，仍可导出初稿；复核版须重新确认。真实案例浏览器回归使用独立数据目录：设置 `BID_AUTH_QA_DIR`，运行 `tests/prepare_authorization_cases.py`，再运行 `tests/test_authorization_flow.cjs`。该回归需要原始考题及本机已核对的证件材料，不修改日常材料库。

### 栏目识别更新（2026-10-22）

系统分别判断“原文需要什么材料”和“图片应插在哪里”。需求可从正文、评分表和附件说明提取，需求证据保留在项目数据中，核对页已移除展开依据和提交要求标签。财务报告年度支持从正文读取和“2024或2025”替代要求。

优先使用实际应答区域和身份证附件表格，识别无标题样式的附件、小节与并列清单边界，避免插入下一栏目。没有正式位置时，按同义名称、材料类型和常见修饰词匹配原文条目，不要求字段名完全相同；通用材料及四类专用材料均支持这一定位规则。相同清单条目择一定位，多个独立专用应答栏目或跨行业共用条目仍需核对。只有识别到通用材料要求、却找不到对应条目或附件位置时才回退到文末。旧项目自动位置规则升级会取消受影响项的旧确认，保留人工指定位置、已选材料和备注。本次未增加专用材料自动选取、PDF/OCR或授权书正文填写。
