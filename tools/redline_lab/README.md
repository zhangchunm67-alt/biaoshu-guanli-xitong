# 废标红线评测台（本地）

一个人工数红线、算系统精确率／召回率的小工具。**只在 127.0.0.1 运行，不上线、不部署。**

提取和计分直接复用 `scripts/eval_redline.py`，与 `REDLINE_EVAL.md` 的口径一致：系统结果取上传后第一步看到的废标红线（本地规则，不调用模型），标注只作为人工金标准。

## 启动

双击仓库根目录的 `启动红线评测.command`，或在仓库根目录执行：

```bash
./.venv/bin/python tools/redline_lab/serve.py
```

浏览器会自动打开 <http://127.0.0.1:8799/>。停止按 `Ctrl+C`。

可选参数：

```bash
--corpus 路径     评测集目录，默认 ./红线评测集
--port 8800       换端口
--no-open         不自动打开浏览器
```

## 用法

1. **导入**：右上角「＋ 导入招标文件」，支持 `.docx` 和 `.doc`（`.doc` 需要本机装有 LibreOffice，由主系统现有的转换逻辑处理）。文件会复制到 `红线评测集/D01-项目名/`。
2. **标注**：左侧是系统读到的采购原文。先选中触发条件所在的一句，再点「＋ 标为红线」，只记录选中的文字；整段都是红线时直接点。右侧可改状态、包件、位置和备注。
   - 建议先盲标，不要打开「显示系统结果」。
   - 状态：`有效` 计入指标；`不适用` 表示原文有、但本项目设置已排除（系统列出即算误报）；`存疑` 不计入任何指标。
3. **计算**：点「计算指标」，得到命中、漏报、误报、精确率、召回率、F1/F2，以及逐条对照和原因归类。
4. **汇总**：点「全部评测」，看所有文件的微平均／宏平均，下载 `report.md` 和 `details.csv`。
5. **归档**：「导出标注表」生成 `红线标注.xlsx`，格式与命令行脚本一致，可直接被 `scripts/eval_redline.py run` 读取。

标注会自动保存到 `红线评测集/D01-项目名/标注.json`；切换文件、点刷新或计算指标前会先落盘。直接关闭页面前，浏览器会提示还有未保存内容。

「导出标注表」会下载 `红线标注.xlsx`，同时把它写回该文件目录，供命令行脚本读取。

## 指标口径

| 指标 | 公式 | 说明 |
| --- | --- | --- |
| 精确率 P | 命中 ÷ 系统条数 | 系统列出的红线有多少是真的 |
| 召回率 R | 命中 ÷ 有效金标条数 | 原文中的红线有多少被列出 |
| F1 / F2 | 调和平均；F2 召回权重为 2 倍 | 单一综合数 |

- 匹配是**一对一**：金标文字按顺序出现在系统条目中的连续覆盖率达到 **0.8** 即配对；一条系统条目只能命中一条金标。
- 未被配对的系统条目会被判为重复、片段、不适用未过滤或误报；未命中的金标会归因为「合并」「归入其他类别」「未识别」「未读取」。
- 主指标是严格口径下的微平均（所有文件合并计数）。界面同时给出宽松口径（合并条目也算列出）和宏平均，参考门槛标为召回 ≥ 95%、精确 ≥ 85%，可按业务调整。
- 金标里同一条文重复时只计一次，界面会在指标下方注明合并条数。

## 数据放在哪

```text
红线评测集/                 # 已在 .gitignore，不提交
  D01-某某项目/
    招标文件.docx
    标注.json              # 本工具的标注状态
    红线标注.xlsx          # 点「导出标注表」生成
  _回收站/                 # 删除的文件移到这里，不直接删
  _报告/                   # 命令行脚本的输出（如使用）
```

原件、标注和报告都只在本机。工具没有登录和权限控制，同一台机器上的其他使用者可以打开页面，请不要把它绑定到 `0.0.0.0`（启动参数已限制为本机地址）。

## 与命令行评测的关系

两者共用同一套提取和计分代码：

- 图形界面适合逐份阅读、划句、看逐条对照；
- `scripts/eval_redline.py` 适合批量复跑、算置信区间和归档；
- 在界面里导出 `红线标注.xlsx` 后，可以执行：

```bash
./.venv/bin/python scripts/eval_redline.py run 红线评测集 --split test
```

`标注.json` 是本工具的编辑状态；`红线标注.xlsx` 是给命令行和其它人看的归档格式。导出时会用当前标注覆盖同名 xlsx。

## 注意

- **只评测系统能读到的内容**。图片、文本框、页眉页脚、嵌入附件里的条款，系统可能读不到；这类漏报在对照表里会显示为「未读取」。以 Word 原件通读为准，原件有、界面原文里没有的条款，仍应标注并备注。
- 金标请**逐字复制**触发条件所在的完整句子或列表项，不要改写。系统条目比金标长不影响覆盖率；金标比系统条目长会拉低覆盖率。
- 建议两名熟悉招投标的人背靠背标注，至少覆盖 1/3 文件的一致性检查（命令行 `agree`），一致性达到 0.90 再作为正式基线。
- 评测结果只代表所选文件，不代表任意采购文件都能完整提取。
- 一个文件提取失败时，该文件所有金标都会记为漏报，界面顶部会红字提示失败原因。
