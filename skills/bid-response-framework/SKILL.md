# 从招标文件生成投标框架

收到“生成框架”时，直接交付可填写、可更新目录的 DOCX。生产输入仅限本次采购方发布的招标文件、附件和补遗。招标件内的“投标文件格式”和空白响应表属于采购材料，按原件采用。即使目录里同时放有投标人旧标或参考框架，也不将其用于生成、补漏或生产验收。

## 辨认范围

- 用户固定编制规则：无论采购原文是否提及，都必须在响应目录和正文中保留投标主体的“营业执照”及材料位置；已有对应章节时不重复添加。新增章节放在“公司介绍”之前，与公司介绍同级；没有公司介绍时放入资格证明部分，否则单列。原文未要求时属于用户补充材料，不虚构采购出处，不计入采购方强制资格要求。
- 标书管理系统在“招标文件解读 → 目录编写”时，仅在采购原文要求商务标、技术标分册时生成各自目录；未要求分册时保留统一目录。采购方的分册名称、顺序、归属及另设资格标按原文保留。营业执照与公司介绍保留完整内容，在同一部分相邻排列，营业执照在前。若原文明确要求分别归入不同分册，保留必交原位置，并在公司介绍前增列营业执照补充材料，说明原因。不得因拆分丢失固定原表、标段或稳定章节标识。页面分别展示各册目录，仍通过同一整本工作稿进入填充。
- 核对封面项目名、采购编号、包件、采购轮次和补遗。一个包件一套编排。标段未选时保留空选项，并在结果中指明待选项。
- 区分采购目录、评审表、实际应答目录与正式附件。有明确应答目录时以此为序，再定位各表。只有材料清单时，按清单排序、按附件还原。仅有附件序列时，以附件排序，从须知、评分、正文说明和表下注补齐。
- 默认覆盖采购要求的全部适用范围。手持、另封、U盘、演示文稿和缺失的附件原表分别注明提交位置与条件。若要求并册和另封各一份，要分别说明。命令每次处理一个 DOCX；技能执行时须逐份核对采购方附件和补遗，按本项目指定的分册与装订要求组装。

## 运行

从本技能目录运行以下命令。使用可导入 `lxml` 的 Python 3.9+。Codex 桌面端可通过工作区依赖工具取得 Python 路径，代替下列 `python3`。输入和产物使用不同文件名。

```sh
python3 scripts/generate.py "本项目招标文件.docx" "本项目_投标文件框架.docx"
```

默认同时交付同名的 `_目录与五类要求.html` 内部编制页。上方显示废标红线条款、强制资格要求、评分细则要点、商务技术规范、指定格式五个实际识别数，下方可展开本次生成的目录、适用范围、条款原文和出处。统计取自整份采购原件；即使仅生成分册，也不要把该分册的标题数量当作采购条款数。

### 识别五类要求

- **废标红线条款。** 核实触发条件与后果。区分“一律否决”和“可能被拒绝”。条款中的星号须与本项目对星号的定义联读。
- **强制资格要求。** 识别投标主体或拟派人员必须满足的准入或资格审查门槛，保留时间、数量、证明材料和任选条件。将履约要求、评分加分条件分别归类。
- **评分细则要点。** 优先核对实际使用的评分表，逐行检查因素、权重、门槛或扣分档次。一个因素的多个得分档合计一项。只有文字权重时按明确的因素列示，统一适用多个包件的规则按其共同范围计数。
- **商务技术规范。** 从报价、商务条件、服务范围、技术规格、交付和验收等采购条款中提取需要供应商逐项落实的要求，保留例外、条件及标段差异。
- **指定格式。** 识别采购原件实际提供的响应附件与固定表式，按原表保留字段、表注和签章位。仅出现附件名称或链接时，注明尚缺原件，不视为已经取得完整格式。

每个数字以本类明细数为准；同范围重复要求保留多个出处，跨类条款可在各自类别出现。逐项从原件反查招标公告、前附表、评审办法、否决条款、采购需求和附件，发现漏项或误报时按[编排计划格式](references/plan-format.md)修订后重建。外置附件或扫描图表尚未读到时披露覆盖范围，零命中表述为“未识别到”。五类要求的分析汇总不写入对外提交的固定表式。仅需统计时可运行 `python3 scripts/tender_metrics.py "本项目招标文件.docx" "五类要求.html"`；传入同源的 `--plan` 可同时展示目录。

采购方明确要求各子项目分别提交独立方案和报价时，默认入口会把指定的 DOCX 用作编制清单，并在同名的 `_独立响应文件` 文件夹生成各项目的方案、报价 Word。按所选子项目使用相应分件，每个报价表保留自己的预算上限和空白报价。清单用于编制核对。

仅在用户明确要求主体与授权分册时，使用下列选项。报价、讲标、财审等要求仍在全项目框架中核对。

```sh
python3 scripts/generate.py "本项目招标文件.docx" "本项目_主体与授权框架.docx" --scope identity-and-authorization
```

自动拟订器识别具备规定目录、材料清单或成组附件的 Word 原件。遇到复杂标段、异常标题或没有规定目录时，由运行技能的 Codex 读取原件，自行编排、生成并按下方流程核对。用户无需编写计划或提供示范标书。

```sh
python3 scripts/build_framework.py inspect "本项目招标文件.docx"
python3 scripts/plan_framework.py "本项目招标文件.docx" "临时目录/计划.json"
python3 scripts/generate.py "本项目招标文件.docx" "本项目_投标文件框架.docx" --plan "临时目录/计划.json"
```

若拟订器无法识别格式，使用 `inspect` 的块序号，按 [编排计划格式](references/plan-format.md) 由 Codex 建立临时计划，再用 `--plan` 生成。采购方未规定表式时，根据实际要求设置标题、可编辑字段与证明材料位置。采购方指定了原表但附件缺失时，保留该表的位置并点名缺失文件。命令仅支持 DOCX；对于 PDF 或扫描件，先提取可辨的正文和正式表式，逐格核对，并标明无法确认的字段。

## 如何判断一章写到哪里

1. 先定位正式表单和每个材料的粒度。法人身份证明和授权委托书即使在同一附件也可分章。资格大项下的投标声明、业绩、人员、财务、其他材料保留相应子层。证件正反面或两种身份各建独立可填写区。
2. 报价函、技术及商务偏离、固定承诺、签字盖章、金额税率栏和合同模板应保留原文原格。表注可能规定年份、期间、合同页、盖章、材料份数或另交方式，分别落到对应表或附件。遇到源材料只给文件名，列出取得原表的待办。
3. 按评分细项为技术和服务章节建立能定位的应答位置。采购要求索引或同类编排需要索引时，保留评分细项、分值、评分口径并加页码栏。评分上限与达标条件只作编制提示；尚待落实的响应时限、业绩、报价、人员及承诺留空。
4. 资格分支仅在相应条件下适用。企业、事业单位、分公司和自然人等依招标文字分开列示。要求“如有”“不少于”“以下任选”时保留限定。负责人社保的月份、缴费人员及证明主体按原件。
5. 一人一表或一案一组按明确要求给足份数。无固定数量时提供可复制的资料组，去掉历史公司的个人信息、案例名称、证照图片和旧目录页码。区分采购人的正式表述与源文件里的投标人工作批注。
6. 证据不足以决定的自拟标题可从服务内容或实际评分项命名。不要搬入旧标的专属策略、虚构方案或得分承诺。

## 多媒体、多标段和嵌入附件

把“每个可投媒体 / 标段 → 必交文件及其表式”逐行核对。通用格式章只写“见第四部分”时，继续找到相应服务方式的原始勾选表、讲标提纲和评分表。某些代运营标需同时交商务应答和 PPT。同一媒体下的备选标段和跨媒体分别交件的条件均要写清，所有选项留空。采购约束原格式时按源表复制，带有评委打分栏的表与供应商自填栏分开处理。

附件标题可能带有必填、无效标、逐项报价或条件性提交要求，这些题注要随原表。检查 DOCX 包中是否真有嵌入原件；只有图标时提示取得原文件，有完整嵌入文件时保留对应对象并复核内容指纹。材料清单中的条件授权与实际附件同名时，在对应条目放一次正式原件。盖章、递交格式和字号先查本项目须知。

## 按采购结构编排

- **分册招标文件。** 先抄准格式章的分册名称、顺序和归属，再展开各册项目。把评审办法的实际因素填入初评、详评索引；每项保留自己的页码或证明位置。技术规范中的实质性条款分别落到方案或偏离表。除非采购要求实际分文件上传，编制阶段可在同一份框架中按册组织。
- **采购平台导出件。** 将商务、技术两部分与平台的报价、服务、评分等表逐项对应。通用须知和项目资料表同时列出多种递交方式时，到项目资料表读选中的方式及其完整定义。保证金按项目字段判断。保留采购数量、限价、单位和评分值；清空示例报价和供应商尚未确认的应答。对只有平台链接的附件保留文件名与取得原件的说明。
- **采购邀请函。** 先确定当前采购阶段和供应商实际需要提交的材料。从事项说明提取授权、报价、递交与签章条件，从需求说明提取服务或证明材料的待填位置。采购方拟好的授权书、声明按原文保留；只要求报名或资格材料的，框架限于该阶段。采购方未给的业务事实留空。
 
## 仅凭采购材料验收

先从采购原件独立列出各标段的必交项、条件项、固定原表和评分项，再逐条在生成的 Word 里定位到正文、相应分册或另交说明。验收清单应来自采购原文；从生成目录反推清单会漏掉整章。查到无落点的要求就修正编排再生成。核对固定表字段、签章位、证明数量与未填选项，打开文档检查宽表、证件框与分页。只有源材料缺失、互相冲突或不可辨时，才在交付时单列待确认事项。目录可在 Word 更新；评分索引页码在最终排版后回填。

### 目录校验

目录生成后先做序号与结构校验，再交付或进入系统填充。`generate.py` 生成后自动输出校验结果；也可单独运行：

```sh
python3 scripts/outline_check.py "本项目_投标文件框架.docx"
```

从招标文件直接拆出的标题常带原文序号（“一、”“1.”“第三章”“（二）”“附件3”），拆分、补章或人工调整后容易错乱。校验逐个同级章节组检查：

- 原文序号乱序、重复、跳号或不从 1 开始。给出按当前顺序重新编号的建议，保留原有样式。
- 同级既有原文序号（“一、”“1.”“第X章”）又有 Word 自动编号的标题，导出后会出现两套编号。建议去掉原文序号，统一自动编号。
- 同级混用多种编号样式，或子章节与上级用同一种样式，多为层级拆错，须对照原文调整层级。
- 附件序号乱序或重复。附件号须与采购原件一致，只提示，不自动改号；按原件调整章节顺序。
- 同级去掉序号后重名，核对是否重复拆分。

有提示时修正计划后重建；采购原件本身跳号（例如部分附件不适用）等确需保留的情形，在交付说明中写明。标书管理系统的“目录编写”页显示同样的校验结果，可按建议修正后保存目录；仍有提示时须勾选“已核对目录校验提示”才能确认目录。

交付框架及必要的范围说明。临时计划、检验记录与渲染图片在验收完成后清理。

## 有人工样本的开发评测

仅在用户另行要求与人工样本对照时使用。先完成上述生产验收、固化成品，再运行只读比较。分别报告同名标题顺序、主章功能和关键表单。

```sh
python3 scripts/compare_framework.py "参考框架.docx" "已生成.docx" --source "本项目招标文件.docx"
```
